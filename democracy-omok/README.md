## 프로젝트 소개

**연결의 한 수 Online**은 모든 플레이어가 동시에 두 곳을 선택하고, 같은 위치를 노린 플레이어끼리는 **투표권**으로 해당 교차점의 소유권을 다투는 실시간 웹 보드게임입니다.

일반 오목처럼 한 명씩 차례대로 돌을 놓는 방식이 아닙니다.

각 플레이어는 자신의 차례가 따로 보이지 않는 상태에서 **두 개의 교차점과 각 위치에 사용할 투표권을 비밀리에 제출**합니다. 모든 플레이어가 제출을 마치면 Supabase가 한꺼번에 판정하고, 결과만 전체 플레이어에게 공개합니다.

이미 다른 돌이 놓인 위치도 다시 선택할 수 있기 때문에, 단순히 빈 공간을 넓히는 것뿐 아니라 **상대의 연결을 빼앗거나 지키는 선택**도 중요합니다.

게임은 총 **5턴** 동안 진행되며, 매 턴 자신의 가장 큰 연결 묶음 크기만큼 점수를 얻습니다. 같은 크기만큼 다음 턴에 사용할 투표권도 받기 때문에, 연결을 크게 만드는 플레이어일수록 이후 충돌에서도 더 강한 선택권을 갖게 됩니다.

## 게임 시작 방법

1. 게임 페이지에 접속합니다.
2. 닉네임과 총 플레이어 수를 입력하고 **방 만들기**를 선택합니다.
3. 생성된 **6자리 방 코드** 또는 초대 링크를 친구에게 공유합니다.
4. 다른 플레이어는 닉네임과 방 코드를 입력하여 참가합니다.
5. 설정한 인원이 모두 들어오면 방장이 **게임 시작**을 선택합니다.
6. 매 턴 각자 두 곳을 선택하고 투표권을 배분한 뒤 제출합니다.
7. 모든 플레이어가 제출하면 서버가 동시에 판정합니다.
8. 5턴이 끝나면 가장 높은 점수를 가진 플레이어가 승리합니다.
9. 게임 종료 후 방장은 같은 방에서 다시 게임을 시작할 수 있습니다.

대기실에서 아직 다른 플레이어가 들어오지 않았다면 방장은 **방 삭제하고 처음으로**를 눌러 방을 삭제하고 첫 화면으로 돌아갈 수 있습니다.

# 게임 규칙

## 1. 바둑판

돌은 칸의 가운데가 아니라 **바둑·오목처럼 선과 선이 만나는 교차점**에 놓습니다.

2명 게임은 **4×4 교차점**, 즉 총 16개의 위치에서 시작합니다.

플레이어가 한 명 늘어날 때마다 가로와 세로 크기가 번갈아 1씩 증가합니다.

| 참여 인원 | 보드 크기 |
|---:|---:|
| 2명 | 4×4 |
| 3명 | 5×4 |
| 4명 | 5×5 |
| 5명 | 6×5 |
| 6명 | 6×6 |
| 7명 | 7×6 |
| 8명 | 7×7 |

보드 크기는 칸의 개수가 아니라 **돌을 놓을 수 있는 교차점의 개수**를 의미합니다.

바둑판은 실제 바둑판처럼 보이도록 가로·세로 선 간격과 돌의 크기 비율을 맞춰 표시합니다.

---

## 2. 한 턴에 두 곳 선택

각 플레이어는 매 턴 **서로 다른 두 교차점**을 선택합니다.

선택한 위치는 다른 플레이어에게 공개되지 않습니다.

모든 플레이어가 제출을 마칠 때까지 다른 사람의 선택을 볼 수 없습니다.

---

## 3. 투표권 배분

플레이어는 자신이 가진 투표권을 선택한 두 위치에 자유롭게 나누어 사용할 수 있습니다.

예를 들어 투표권이 4개라면 다음과 같이 사용할 수 있습니다.

- 첫 번째 위치 4표 / 두 번째 위치 0표
- 첫 번째 위치 3표 / 두 번째 위치 1표
- 첫 번째 위치 2표 / 두 번째 위치 2표

투표권을 어디에 얼마나 집중할지가 중요한 전략 요소입니다.

---

## 4. 같은 위치를 여러 명이 선택했을 때

같은 교차점을 두 명 이상이 선택하면 그 위치에 사용한 **투표권 수**를 비교합니다.

가장 많은 투표권을 사용한 플레이어가 해당 위치를 차지합니다.

예시:

- A 플레이어: 3표
- B 플레이어: 1표
- C 플레이어: 2표

→ A 플레이어가 해당 교차점을 차지합니다.

### 최고 투표수가 동률일 경우

최고 투표수가 같은 플레이어가 둘 이상이면 **그 위치의 기존 상태를 유지**합니다.

즉 기존에 돌이 있었다면 그대로 남고, 빈 위치였다면 빈 상태로 유지됩니다.

---

## 5. 이미 돌이 있는 위치도 선택 가능

빈 교차점만 선택할 수 있는 게임이 아닙니다.

이미 자신의 돌이나 상대 돌이 놓여 있는 위치도 다시 선택할 수 있습니다.

따라서 상대의 핵심 연결 지점을 더 많은 투표권으로 빼앗거나, 자신의 중요한 연결 지점을 다시 지키는 플레이가 가능합니다.

---

## 6. 연결 판정

돌의 연결은 **상·하·좌·우**만 인정합니다.

대각선으로 닿아 있는 돌은 연결된 것으로 계산하지 않습니다.

예를 들어 자신의 돌이 상하좌우로 4개 이어져 있다면 최대 연결 크기는 4입니다.

---

## 7. 점수 획득

매 턴 판정이 끝난 뒤 각 플레이어의 **가장 큰 연결 묶음의 돌 개수**를 계산합니다.

그 개수만큼 점수를 획득합니다.

예시:

- 최대 연결 1개 → +1점
- 최대 연결 3개 → +3점
- 최대 연결 5개 → +5점

여러 연결 묶음이 있더라도 그중 **가장 큰 하나**를 기준으로 계산합니다.

---

## 8. 다음 턴 투표권

다음 턴에 사용할 수 있는 투표권도 자신의 **최대 연결 크기**와 같습니다.

예를 들어 이번 턴 종료 후 최대 연결이 4라면 다음 턴에는 투표권 4개를 사용할 수 있습니다.

즉 큰 연결을 만들면:

**점수 증가 → 다음 턴 투표권 증가 → 다음 충돌에서 더 강한 영향력 확보**

이라는 흐름이 만들어집니다.

---

## 9. 턴 진행

한 턴은 다음 순서로 진행됩니다.

1. 모든 플레이어가 두 교차점을 선택합니다.
2. 각 위치에 사용할 투표권을 배분합니다.
3. 자신의 계획을 비밀리에 제출합니다.
4. 모든 플레이어가 제출할 때까지 기다립니다.
5. Supabase 데이터베이스에서 모든 선택을 동시에 판정합니다.
6. 충돌 결과에 따라 바둑돌 소유권을 갱신합니다.
7. 각 플레이어의 최대 연결 크기를 계산합니다.
8. 연결 크기만큼 점수를 지급합니다.
9. 연결 크기만큼 다음 턴 투표권을 지급합니다.
10. 모든 플레이어가 다음 턴 준비를 누르면 다음 턴으로 이동합니다.

---

## 10. 게임 종료

게임은 총 **5턴** 진행됩니다.

5턴 종료 후 누적 점수가 가장 높은 플레이어가 승리합니다.

최고 점수가 같은 플레이어가 여러 명이면 공동 승리로 처리됩니다.

# 온라인 멀티플레이 구조

이 게임은 한 컴퓨터에서 여러 명이 번갈아 플레이하는 방식이 아닙니다.

각 플레이어는 자신의 컴퓨터 또는 휴대폰에서 같은 게임 페이지에 접속합니다.

```text
플레이어 A ─┐
플레이어 B ─┼── GitHub Pages ── Supabase
플레이어 C ─┘                       │
                                    ├─ 방 정보
                                    ├─ 플레이어 정보
                                    ├─ 바둑판 상태
                                    ├─ 점수 / 투표권
                                    ├─ 비밀 제출
                                    └─ 실시간 동기화
```

GitHub Pages는 게임 화면을 제공하고, Supabase는 멀티플레이 게임의 데이터와 판정을 담당합니다.

---

## 비밀 선택 보호

각 플레이어의 선택은 제출 즉시 다른 플레이어 화면에 공개되지 않습니다.

비밀 수는 Supabase의 서버 측 로직을 통해 처리하며, 일반 클라이언트가 다른 플레이어의 제출 내용을 직접 읽을 수 없도록 구성했습니다.

모든 플레이어의 제출이 끝난 뒤 판정 결과만 공개됩니다.

---

## 실시간 동기화

Supabase Realtime을 사용합니다.

다음과 같은 변화가 발생하면 다른 플레이어 화면에도 자동으로 반영됩니다.

- 새로운 플레이어 입장
- 게임 시작
- 플레이어 제출 상태
- 턴 판정 완료
- 다음 턴 이동
- 게임 종료

# 방 기능

## 방 만들기

방장은 닉네임과 총 플레이어 수를 입력해 새로운 방을 생성할 수 있습니다.

방에는 6자리 코드가 부여됩니다.

## 방 참가

다른 플레이어는 방 코드와 닉네임을 입력해 참가합니다.

## 초대 링크

현재 방 코드가 포함된 초대 링크를 복사해 친구에게 전달할 수 있습니다.

## 빈 방 삭제

대기실에서 방장 혼자만 있는 경우 **방 삭제하고 처음으로** 버튼이 표시됩니다.

이 버튼을 사용하면 빈 방 데이터를 삭제하고 게임 첫 화면으로 돌아갑니다.

다른 플레이어가 이미 참가한 경우에는 방 삭제 버튼을 사용할 수 없습니다.

# 프로젝트 파일

```text
/
├─ index.html
└─ config.js
```

### index.html

게임 화면, 바둑판 렌더링, 사용자 입력, Supabase 통신을 담당합니다.

### config.js

게임에서 사용할 Supabase Project URL과 Publishable Key가 들어 있습니다.

`service_role` 또는 Secret Key는 브라우저 코드에 넣으면 안 됩니다.

---

# 수정 및 배포

게임 화면이나 디자인을 수정했다면 GitHub 저장소의 `index.html`을 변경하고 커밋합니다.

GitHub Pages가 새 커밋을 자동으로 다시 배포하며, 기존 게임 주소는 그대로 유지됩니다.

Supabase 주소나 Publishable Key가 변경된 경우에는 `config.js`를 수정합니다.

게임 판정 규칙이나 데이터베이스 로직을 변경한 경우에는 해당 SQL 함수를 Supabase SQL Editor에서 업데이트해야 합니다.

# 수동 검증 체크리스트

현재 버전은 다음 흐름을 기준으로 확인할 수 있습니다.

- 2명 이상이 서로 다른 브라우저에서 같은 방에 참가되는지
- 설정한 최대 인원이 모두 들어왔을 때 게임이 시작되는지
- 두 위치 선택과 투표권 배분이 정상 동작하는지
- 다른 플레이어의 선택이 제출 전 공개되지 않는지
- 같은 위치 선택 시 더 많은 투표권을 사용한 플레이어가 차지하는지
- 최고 투표수가 동률일 때 기존 돌이 유지되는지
- 이미 돌이 있는 위치를 다시 선택할 수 있는지
- 상하좌우 연결만 계산되는지
- 연결 크기만큼 점수와 다음 턴 투표권이 지급되는지
- 5턴 뒤 게임이 종료되는지
- 게임 종료 후 같은 방에서 다시 시작할 수 있는지
- 방장 혼자 있는 대기실에서 방을 삭제하고 첫 화면으로 돌아갈 수 있는지

# 현재 버전의 특징

**연결의 한 수 Online**은 단순히 돌을 많이 놓는 게임이 아닙니다.

어느 위치가 상대에게 중요한지 예상하고, 제한된 투표권을 어느 두 곳에 집중할지 판단해야 합니다.

연결을 크게 만들수록 점수뿐 아니라 다음 턴의 투표권도 늘어나기 때문에, 작은 연결 하나가 이후 턴의 영향력 차이로 이어질 수 있습니다.

**두 곳을 고르는 선택, 투표권을 나누는 선택, 상대의 연결을 끊을지 자신의 연결을 키울지 결정하는 선택**이 게임의 핵심입니다.
